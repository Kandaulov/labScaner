# labScaner — описание проекта и требования

## 1. Назначение

Сократить ручную работу преподавателя по приёму, раскладке и первичной проверке
студенческих работ (лабораторные, курсовые), сохранив за преподавателем окончательное решение.

Успех =
- ни одна присланная работа не потеряна и лежит в предсказуемом месте на Яндекс Диске;
- журнал группы в любой момент показывает актуальное состояние сдачи;
- первичный ИИ-аудит готов к моменту, когда преподаватель открывает работу;
- студент получает понятный ответ по каждой работе только после подтверждения преподавателя.

## 2. Пользователи

| Роль | Кто | Как работает с системой |
|---|---|---|
| Преподаватель | Несколько пользователей; у каждого свои предметы, почтовый ящик и Яндекс Диск | Веб-интерфейс за паролем, видит только своё |
| Студент | Отправитель писем | Только почта: шлёт работы, получает ответы. В интерфейс не входит |
| Администратор | Один из преподавателей с доп. правами | Пользователи, общие справочники (группы, студенты, календарь), настройки LLM |

## 3. Ключевые сущности (глоссарий)

- **Предмет (Subject)** — дисциплина. Содержит перечень работ, шаблоны отчётов, справочные
  материалы для LLM, чек-листы и тип итоговой аттестации: *экзамен*, *зачёт*, *дифференцированный зачёт*.
- **Группа (Group)** — учебная группа; один предмет может читаться нескольким группам.
- **Учебный семестр (Term)** — например, «2026-2027, осенний». Календарь: начало зачётной недели, начало сессии.
- **Предмет в семестре (SubjectTerm)** — предмет, читаемый в конкретном семестре конкретным группам
  (например, «КорпИС, 2026-2027, ИСТ, 7 сем»). Хранит корневую папку на Диске, набор работ и дедлайны.
- **Дедлайн** — лабораторные: начало зачётной недели; курсовая: начало сессии (можно переопределить для работы).
- **Автомат** — итоговая отметка без экзамена/зачёта для студентов, сдавших всё в срок. Система определяет
  претендентов, решение — за преподавателем.
- **Студент (Student)** — ФИО, группа, e-mail (один или несколько).
- **Работа (Assignment)** — лабораторная №N или курсовая в рамках предмета в семестре. Задание загружается
  DOCX-файлом; дополнительно — чек-лист для проверки. Курсовая — один отчёт DOCX.
- **Предметы на старте:** КорпИС, ОС, СПП. У каждого — свой набор лабораторных.
- **Входящее письмо (InboxMessage)** — письмо студента; может содержать несколько лаб (ADR-022).
- **Сдача (Submission)** — конкретная присылка одной работы студентом. Одно письмо может дать несколько сдач.
  Повторная присылка = новая версия.
- **ИИ-проверка (AiCheck)** — результат аудита LLM: выполнение пунктов чек-листа, полнота разделов,
  согласованность чисел, замечания, предлагаемая оценка (если применимо).
- **Решение преподавателя (Review)** — принято/на доработку, оценка, замечания, флаг «отправить уведомление».
  Оценка за курсовую хранится здесь же (ADR-020).
- **Уведомление (Notification)** — одно письмо студенту по одному предмету в семестре, собирающее решения
  по нескольким работам (ADR-018).
- **Журнал** — таблица по группе и предмету: студенты × работы + курсовая (дата, оценка) +
  экзамен/зачёт (дата, оценка или отметка).

## 4. Функциональные требования

### 4.1 Приём почты
- F1. Система периодически (по умолчанию раз в 5 минут, можно выключить) читает по IMAP выделенный ящик
  университета. Есть кнопка «Проверить почту сейчас» с показом результата; статус приёма виден постоянно.
- F2. Тема письма разбирается по формату `{Группа} – {Предмет} – {ФИО} – Лаб №{N}` (правила — ADR-010)
  → группа, предмет, студент, работа. В теме может быть список или диапазон лаб (`Лаб №3, 4`, `Лаб 3-5`);
  каждый файл письма сопоставляется со своей лабой по имени файла, заголовку на первой странице
  или методом исключения (ADR-022).
- F3. Принимаются только вложения PDF и DOCX; прочие форматы не сохраняются, фиксируются предупреждением
  и показываются в карточке сдачи списком «Не принятые вложения» (ADR-023).
- F4. Нераспознанное письмо не теряется: попадает в очередь «Нераспознанные» для ручного сопоставления.
  Если распознана часть файлов письма, они идут дальше, а на ручное сопоставление попадают только остальные.
- F5. Обработка идемпотентна по `Message-ID`. Обработанное письмо помечается в ящике (флаг/папка).
- F6. Студенту может уходить автоответ «работа получена» (настраивается, по умолчанию выкл.).

### 4.2 Хранение
- F7. Файлы сначала кладутся во временную папку приложения на Яндекс Диске, затем переносятся
  в корневую папку предмета в семестре (существующая папка преподавателя, например
  `30 Политех/03 КорпИС/10 КорпИС - Отчетные документы/2026-2027 КорпИС ИСТ - 7 сем`)
  в папку `{Группа} - ЛР` или `{Группа} - Кр` с именем вида `Лаб 03 - Иванов И.И. - v1.docx` (ADR-011).
- F8. Повторная сдача не перезаписывает предыдущую — создаётся новая версия; актуальна последняя.

### 4.3 ИИ-проверка
- F9. Из файла извлекается текст: DOCX, PDF с текстовым слоем; PDF без текста (сканы) распознаются
  локально OCR (ADR-019). Если текст получить не удалось → статус «нужна ручная проверка» (ADR-021).
- F10. LLM получает: задание, чек-лист, справочные материалы предмета, текст работы без персональных данных.
- F11. LLM возвращает структурированный результат (JSON по схеме): пункты чек-листа (выполнен/частично/нет + комментарий),
  общие замечания, предлагаемая оценка, уверенность.
- F12. Проверка для предмета/работы может быть выключена.
- F13. Результат записывается в журнал системы со ссылкой на сдачу; повторная проверка возможна вручную.

### 4.4 Журнал и решение преподавателя
- F13a. Лаба считается сданной «в срок», если преподаватель принял её не позже дедлайна (ADR-013).
  За 7 и 2 дня до дедлайна система напоминает о сданных, но не принятых работах.
- F14. Журнал в разрезе группы и предмета: ФИО, по каждой работе — дата сдачи, статус, оценка;
  курсовая — дата и оценка; экзамен — дата и оценка, либо отметка о зачёте.
  Статусы ячейки и пометки (версия, уведомление, комментарии) — ADR-017.
- F15. Карточка сдачи: файлы (ссылки на Диск), результат ИИ, поля оценки и замечаний, кнопки
  «Принять», «На доработку», флажок «Отправить уведомление».
- F15a. Быстрая отметка в ячейке журнала без открытия карточки: «ОК» или оценка (работа принята устно).
- F16. Итоговые оценки (курсовая, экзамен, зачёт) вводятся только вручную. Оценка курсовой — в решении
  по принятой версии; итоговая аттестация ссылается на него (ADR-020).
- F16a. Журнал показывает признак «претендует на автомат» (все лабы приняты в срок и курсовая принята
  в срок, если она есть в предмете); преподаватель
  выставляет автомат выбранным одним действием: «зачтено» для зачёта, «5» для экзамена.
- F16b. По каждой лабе в журнале группы доступна история комментариев: замечания ИИ, замечания
  преподавателя, что отправлено студенту, пересдачи.

### 4.5 Уведомления
- F17. Решения с флажком «отправить уведомление» собираются в одно письмо на студента и предмет в семестре:
  по каждой подтверждённой работе — статус, оценка (если есть), замечания (если есть) (ADR-018).
- F18. Письмо уходит только после явной отправки преподавателем с предпросмотром. Отправка — через очередь
  с повторами.
- F19. Отметка «уведомление отправлено» с датой видна в журнале.

### 4.6 Администрирование
- F20. Справочники: предметы, учебные семестры (календарь), предметы в семестре (группы, папка на Диске,
  дедлайны), задания: один DOCX на все лабы (делится на работы по заголовкам) и один DOCX на курсовую;
  группы, студенты (импорт из CSV/XLSX).
- F21. Настройки подключений: IMAP, SMTP, Яндекс Диск, LLM; шаблоны писем.
- F22. Журнал событий: лента «Что ждёт от меня» (задачи преподавателю) и полная лента того, что система
  сделала: что пришло, что распознано, ошибки внешних сервисов.
- F23. Журнал проверки работы: ход обработки каждой сдачи по шагам с временем, ошибками и повтором шага;
  общий список сдач, находящихся в обработке.

## 5. Нефункциональные требования

- НФ1. Размещение — VPS, Docker Compose, HTTPS обязателен.
- НФ2. Вход по паролю; хранится только хеш; ограничение попыток входа.
- НФ3. Персональные данные студентов (ФИО, e-mail, работы) не уходят в LLM в открытом виде (152-ФЗ).
  Изображения страниц в LLM не отправляются; OCR — только локально (ADR-019).
- НФ4. Сбой одного внешнего сервиса не останавливает остальную обработку; повторы с backoff
  только для временных сбоев (ADR-021).
- НФ5. Ежедневный бэкап PostgreSQL.
- НФ6. Нагрузка небольшая: до ~10 групп, ~300 студентов, ~3000 сдач за семестр.

## 6. Основные сценарии

1. **Студент сдаёт лабу.** Письмо → разбор темы → файл на Диске → текст (при скане — OCR) → ИИ-проверка → ячейка журнала «Ждёт проверки».
2. **Студент сдаёт несколько лаб одним письмом.** Тема `… – Лаб №5, 6`, три файла → каждый файл сопоставлен с лабой → две ячейки «В обработке»; файл, который не удалось сопоставить, — в «Нераспознанные».
3. **Преподаватель проверяет.** Журнал → ячейка → карточка → правит оценку/замечания → «Принять» + «Отправить уведомление» → решение попадает в письмо-черновик студенту.
4. **Отправка ответа.** Экран «Уведомления» → предпросмотр письма по студенту и предмету (может включать несколько лаб) → «Отправить».
5. **Студент пересдаёт.** Новое письмо по той же работе → версия v2 → ячейка снова «В обработке» → «Ждёт проверки» с пометкой v2, история сохранена.
6. **Письмо с ошибкой в теме.** → «Нераспознанные» → преподаватель вручную указывает студента и работу → дальше по сценарию 1.
7. **Сессия.** Преподаватель вносит дату и оценку экзамена / отметку о зачёте в журнале.

## 7. Вне рамок первой версии

- Личный кабинет студента.
- Проверка на заимствования (антиплагиат).
- Учёт посещаемости.
- Отправка изображений работ в мультимодальную LLM.
