# Развёртывание labScaner на сервере — пошагово

Инструкция для первого запуска на чистом сервере (VPS Timeweb Cloud с Ubuntu). Каждый шаг — что сделать,
какую команду вставить и что должно получиться. Команды копируйте целиком, по одной.

**Время:** около часа, из них 10–15 минут — ожидание сборки.

## 0. Что понадобится

| Что | Где взять |
|---|---|
| **IP-адрес сервера** и **пароль root** | Панель Timeweb Cloud → ваш сервер → «Доступ» (пароль приходит и на почту) |
| Сервер на **Ubuntu 22.04 или 24.04**, от **2 ГБ** памяти и **20 ГБ** диска | Если памяти 1 ГБ — шаг 5 обязателен |
| Аккаунт **GitHub** с доступом к репозиторию `Kandaulov/labScaner` | Ваш |
| Компьютер с Windows 10/11 | Программа «Терминал» или PowerShell уже есть |
| Домен (например, `labs.example.ru`) | **Не обязательно сейчас.** Без домена сайт откроется по IP |

**Про .NET SDK на сервере.** Он не нужен: приложение собирается и работает внутри Docker, там свой .NET.
Удалять его не обязательно — он ничему не мешает.

**Как читать команды.** Текст в серых блоках — команды для сервера. Где написано `<что-то в угловых скобках>`,
подставьте своё значение **без скобок**. Строки, начинающиеся с `#`, — пояснения, их вводить не нужно.

## 1. Подключиться к серверу

1. На своём компьютере откройте **Пуск → Терминал** (или **PowerShell**).
2. Введите (вместо `<IP>` — адрес сервера, например `85.193.80.12`):
   ```
   ssh root@<IP>
   ```
3. При первом подключении спросят `Are you sure you want to continue connecting?` — напишите `yes` и нажмите Enter.
4. Введите пароль root. **Символы при вводе не отображаются** — это нормально. Вставить пароль из буфера можно
   правой кнопкой мыши.
5. Получилось, если строка приглашения стала похожа на `root@имя-сервера:~#`.

Проверьте версию системы:
```
cat /etc/os-release | head -2
```
Должно быть `Ubuntu 22.04…` или `Ubuntu 24.04…`. Если другая система — напишите мне, команды будут отличаться.

> Отключиться от сервера — команда `exit`. Окно терминала можно закрыть: на сервере ничего не остановится.

## 2. Обновить систему и настроить время

```
apt update && apt upgrade -y
```
Займёт 1–5 минут. Если появится розовое окно с вопросом про сервисы или конфигурацию — нажмите **Enter**
(оставить как предлагается).

Часовой пояс — Ульяновск (UTC+4), чтобы время в журналах совпадало с вашим:
```
timedatectl set-timezone Europe/Ulyanovsk
```

Если после обновления в выводе было `*** System restart required ***`, перезагрузите сервер и подключитесь заново
через минуту:
```
reboot
```

## 3. Создать рабочего пользователя

Работать под `root` небезопасно: одна опечатка может сломать систему. Создадим пользователя `deploy`.

```
adduser deploy
```
Придумайте и дважды введите пароль (символы не видны). На вопросы «Full Name», «Room Number» и т. п. просто
нажимайте Enter, в конце — `Y`.

Дайте ему права администратора:
```
usermod -aG sudo deploy
```

Отключитесь и зайдите уже под `deploy`:
```
exit
```
```
ssh deploy@<IP>
```
Приглашение должно стать `deploy@имя-сервера:~$`. **Дальше всё делаем под `deploy`.**
Команды с `sudo` попросят пароль пользователя `deploy` (не root).

## 4. Включить файрвол

Файрвол закрывает все входящие подключения, кроме нужных: SSH (чтобы вы могли зайти), 80 и 443 (сайт).

> **Важно:** команды выполняйте строго по порядку. Если включить файрвол, не разрешив SSH, вы потеряете доступ
> к серверу (восстановить можно через консоль в панели Timeweb).

```
sudo ufw allow OpenSSH
```
```
sudo ufw allow 80/tcp
```
```
sudo ufw allow 443/tcp
```
```
sudo ufw enable
```
На вопрос `Proceed with operation (y|n)?` ответьте `y`. Проверка:
```
sudo ufw status
```
Должны быть строки `OpenSSH`, `80/tcp`, `443/tcp` со словом `ALLOW`.

## 5. Добавить файл подкачки

Сборке приложения нужно около 2 ГБ памяти. Файл подкачки страхует от ошибки «не хватило памяти»,
если у сервера 1–2 ГБ. Посмотреть, сколько памяти и есть ли подкачка:
```
free -h
```
Если в строке `Swap:` стоит `0B` — добавьте 2 ГБ подкачки (четыре команды по очереди):
```
sudo fallocate -l 2G /swapfile
```
```
sudo chmod 600 /swapfile
```
```
sudo mkswap /swapfile && sudo swapon /swapfile
```
```
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```
Снова `free -h` — в строке `Swap:` должно быть `2.0Gi`.

## 6. Установить Docker

Docker запускает приложение, базу данных и веб-сервер в изолированных «контейнерах».

### Способ А — официальный репозиторий Docker (рекомендуется)

Скопируйте и выполните блок целиком:
```
sudo apt install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Если на команде `curl` ошибка (`Could not resolve`, `403`, `timed out`) — сайт Docker недоступен.
Удалите добавленный источник и используйте способ Б:
```
sudo rm -f /etc/apt/sources.list.d/docker.list && sudo apt update
```

### Способ Б — из репозитория Ubuntu (если способ А не сработал)

```
sudo apt install -y git docker.io docker-compose-v2 docker-buildx
```

### После установки (для обоих способов)

Разрешите пользователю `deploy` управлять Docker без `sudo`:
```
sudo usermod -aG docker deploy
```
**Отключитесь (`exit`) и подключитесь снова** — иначе права не применятся. Проверка:
```
docker --version && docker compose version
```
Должны вывестись две версии, например `Docker version 27.x` и `Docker Compose version v2.x`.

## 7. Подключить зеркало Docker Hub

Готовые образы (PostgreSQL, Caddy) скачиваются с Docker Hub. Из России он временами блокируется, поэтому сразу
подключим зеркало Timeweb — оно бесплатное и работает и как запасной путь.

```
echo '{ "registry-mirrors": ["https://dockerhub.timeweb.cloud"] }' | sudo tee /etc/docker/daemon.json
```
```
sudo systemctl restart docker
```
Проверка — скачивание и запуск тестового образа:
```
docker run --rm hello-world
```
Получилось, если среди вывода есть `Hello from Docker!`.

## 8. Скачать код с GitHub

Репозиторий закрытый, поэтому серверу нужен **токен** — отдельный пароль только на чтение этого репозитория.

### 8.1. Создать токен (на своём компьютере, в браузере)

1. Откройте [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new)
   (GitHub → аватар справа вверху → **Settings** → **Developer settings** → **Personal access tokens** →
   **Fine-grained tokens** → **Generate new token**).
2. **Token name:** `labscaner-server`. **Expiration:** 1 год (или как удобно).
3. **Repository access:** **Only select repositories** → выберите `Kandaulov/labScaner`.
4. **Permissions → Repository permissions → Contents:** **Read-only**. Остальное не трогайте.
5. Нажмите **Generate token** и **сразу скопируйте** токен (начинается с `github_pat_…`) — второй раз его не покажут.
   Сохраните в менеджер паролей.

### 8.2. Скачать репозиторий (на сервере)

```
git clone https://github.com/Kandaulov/labScaner.git ~/labscaner
```
- `Username:` — `Kandaulov`
- `Password:` — вставьте **токен** (не пароль от GitHub!). Символы не видны.

Чтобы при обновлениях не вводить токен каждый раз, сохраните его на сервере
(он запишется в файл `~/.git-credentials`, доступный только пользователю `deploy`):
```
git -C ~/labscaner config credential.helper store
```
Токен запомнится при следующем `git pull` (шаг 13).

Проверка:
```
ls ~/labscaner/deploy
```
Должны быть файлы `Caddyfile`, `docker-compose.yml`, `Dockerfile`, `README.md`.

## 9. Заполнить настройки

Все настройки хранятся в файле `.env` в папке `deploy`. Создаём его из образца:
```
cd ~/labscaner/deploy && cp .env.example .env
```

Сгенерируйте два надёжных пароля — для базы данных и для администратора. Выполните команду **два раза**
и запишите оба результата:
```
openssl rand -hex 16
```

Откройте файл в редакторе:
```
nano .env
```
Перемещайтесь стрелками. Заполните строки (значения — после `=`, без пробелов вокруг `=` и без кавычек):

| Строка | Что вписать |
|---|---|
| `DOMAIN=` | **IP-адрес сервера**, пока нет домена (например, `DOMAIN=85.193.80.12`) |
| `DB_PASSWORD=` | первый сгенерированный пароль |
| `ADMIN_LOGIN=` | логин для входа, например `kandaulov` (латиница, без пробелов) |
| `ADMIN_PASSWORD=` | второй сгенерированный пароль (или свой, **не короче 10 символов**) |
| `ADMIN_DISPLAY_NAME=` | как вас показывать в системе, например `Кандаулов В. М.` |
| `APP_IMAGE=` | замените на `APP_IMAGE=labscaner:local` — образ соберём прямо на сервере |
| `YANDEX_CLIENT_ID=` | **ClientID** приложения Яндекса (oauth.yandex.ru → приложение «labScaner») |
| `YANDEX_CLIENT_SECRET=` | **Client secret** того же приложения |

Сохранить: **Ctrl+O**, затем **Enter**. Выйти: **Ctrl+X**.

Закройте файл от посторонних глаз:
```
chmod 600 .env
```

> **ClientID и секрет Яндекса** нужны, чтобы преподаватели могли подключить свой Диск («Настройки → Яндекс Диск»).
> Если вписали их позже — перезапустите приложение: `docker compose up -d`.

> **Пароль администратора** понадобится для входа на сайт. **Пароль БД** вводить никуда не нужно —
> он только связывает приложение с базой. Оба храните в менеджере паролей.

## 10. Запустить

Из папки `~/labscaner/deploy`:
```
docker compose up -d --build
```
Что происходит:
1. Скачиваются образы PostgreSQL, Caddy и .NET (несколько сотен мегабайт).
2. Собирается приложение — **5–15 минут** при первом запуске. Ждите, пока снова не появится приглашение `deploy@…$`.
3. Стартуют три контейнера: база, приложение, Caddy.

Проверка (повторите через минуту, если `app` ещё в `starting`):
```
docker compose ps
```
Получилось, если у всех трёх контейнеров в колонке `STATUS` есть `Up`, а у `app` — `(healthy)`:
```
NAME               SERVICE   STATUS
labscaner-app-1    app       Up 2 minutes (healthy)
labscaner-caddy-1  caddy     Up 1 minute
labscaner-db-1     db        Up 2 minutes (healthy)
```

При первом старте приложение само создаёт таблицы в базе и администратора из `.env`.

## 11. Проверить в браузере

1. Откройте `https://<IP-сервера>` (именно **https**).
2. Браузер предупредит: «Подключение не защищено» / «Ваше подключение не является закрытым». Это ожидаемо:
   без домена сертификат выпускается самим сервером, и браузер ему не доверяет.
   Нажмите **«Дополнительно» → «Перейти на сайт (небезопасно)»**.
3. Откроется страница **«Вход»**. Введите `ADMIN_LOGIN` и `ADMIN_PASSWORD` из `.env`.
4. Должна открыться **Сводка** с вашим именем внизу меню.

Готово — система работает. Предупреждение о сертификате пропадёт, когда подключите домен (шаг 12).

## 12. Подключить домен (когда будет)

1. В панели, где куплен домен (или в Timeweb Cloud → **Домены и SSL**), добавьте **A-запись**:
   имя — `@` (или поддомен, например `labs`), значение — **IP сервера**.
2. Подождите от 15 минут до нескольких часов. Проверить, что домен «смотрит» на сервер:
   ```
   getent hosts <ваш-домен>
   ```
   Должен вывестись IP сервера.
3. Впишите домен в настройки:
   ```
   cd ~/labscaner/deploy && nano .env
   ```
   `DOMAIN=<ваш-домен>` → Ctrl+O, Enter, Ctrl+X.
4. Перезапустите веб-сервер:
   ```
   docker compose up -d
   ```
5. Через минуту откройте `https://<ваш-домен>` — замок в адресной строке, без предупреждений. Сертификат
   Let's Encrypt Caddy получает и продлевает сам. Для этого порты 80 и 443 должны быть открыты (шаг 4).

## 13. Обновлять на новую версию

Когда в GitHub появилась новая версия (я сообщу), на сервере:
```
cd ~/labscaner && git pull
```
```
cd deploy && docker compose up -d --build
```
Сборка займёт несколько минут; во время неё старая версия продолжает работать. Изменения базы данных
применяются автоматически при старте новой версии. Затем удалите старые образы, чтобы не занимали диск:
```
docker image prune -f
```

> Перед крупными обновлениями сделайте резервную копию (шаг 14) — одна команда.

## 14. Резервные копии

### Сделать копию вручную

```
mkdir -p ~/backups && cd ~/labscaner/deploy
```
```
docker compose exec -T db pg_dump -U labscaner labscaner | gzip > ~/backups/labscaner-$(date +%F).sql.gz
```
Проверка — файл появился и не пустой:
```
ls -lh ~/backups
```

### Ежедневная автоматическая копия

```
crontab -e
```
Если спросят, какой редактор, — выберите `1` (nano). В конец файла вставьте **одну строку**:
```
30 3 * * * cd /home/deploy/labscaner/deploy && docker compose exec -T db pg_dump -U labscaner labscaner | gzip > /home/deploy/backups/labscaner-$(date +\%F).sql.gz && find /home/deploy/backups -name '*.sql.gz' -mtime +14 -delete
```
Сохраните (Ctrl+O, Enter, Ctrl+X). Копия будет делаться каждую ночь в 3:30, храниться 14 дней.

### Скачать копию к себе на компьютер

В терминале **своего компьютера** (не сервера):
```
scp deploy@<IP>:~/backups/labscaner-<дата>.sql.gz .
```
Файл окажется в текущей папке (обычно `C:\Users\<вы>`).

### Ключи шифрования

Кроме базы, есть ключи, которыми шифруются входы и пароли подключений (почта, позже — Диск и ключ ИИ). Без них после
восстановления на другом сервере пароли подключений придётся вводить заново. Копия ключей:
```
docker run --rm -v labscaner_keys:/keys -v ~/backups:/b alpine tar czf /b/keys-$(date +%F).tgz -C /keys .
```

### Восстановить базу из копии

> Это **заменит** текущие данные данными из копии.

```
cd ~/labscaner/deploy && docker compose stop app
```
```
docker compose exec -T db psql -U labscaner -d postgres -c "DROP DATABASE labscaner WITH (FORCE);" -c "CREATE DATABASE labscaner OWNER labscaner;"
```
```
gunzip -c ~/backups/labscaner-<дата>.sql.gz | docker compose exec -T db psql -U labscaner -d labscaner
```
```
docker compose start app
```

## 15. Повседневные команды

Все — из папки `~/labscaner/deploy` (`cd ~/labscaner/deploy`).

| Задача | Команда |
|---|---|
| Состояние контейнеров | `docker compose ps` |
| Журнал приложения (последние 100 строк) | `docker compose logs --tail 100 app` |
| Журнал в реальном времени (выход — Ctrl+C) | `docker compose logs -f app` |
| Перезапустить приложение | `docker compose restart app` |
| Остановить всё (данные сохранятся) | `docker compose down` |
| Запустить снова | `docker compose up -d` |
| Свободное место на диске | `df -h /` |
| Сколько места занимает Docker | `docker system df` |

> **Никогда не выполняйте** `docker compose down -v` и `docker volume rm …` — флаг `-v` **удаляет базу данных**.

## 16. Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `permission denied … docker.sock` | Не перезашли после шага 6. Выполните `exit`, подключитесь снова |
| `toomanyrequests`, `403 Forbidden`, `timeout` при скачивании образов | Проверьте шаг 7 (зеркало). `cat /etc/docker/daemon.json`, затем `sudo systemctl restart docker` |
| Ошибка скачивания с `mcr.microsoft.com` (образы .NET) | Зеркало Docker Hub на них не действует. Повторите через несколько минут; если не проходит — пришлите мне текст ошибки |
| Сборка оборвалась, в выводе `Killed` или `exit code 137` | Не хватило памяти — сделайте шаг 5 и повторите `docker compose up -d --build` |
| `Задайте DB_PASSWORD в .env` / `Задайте ADMIN_PASSWORD в .env` | В `.env` пустая строка — шаг 9 |
| `Bind for 0.0.0.0:80 failed: port is already allocated` | Порт занят другим веб-сервером. Посмотреть кем: `sudo ss -tlpn \| grep -E ':80\|:443'`. Если это `apache2` или `nginx`, который вам не нужен: `sudo systemctl disable --now apache2` (или `nginx`) |
| `app` долго в `starting` или `unhealthy` | `docker compose logs --tail 50 app` — ищите строки `fail:` или `Exception` |
| Сайт не открывается совсем | `docker compose ps` — все ли `Up`; `sudo ufw status` — открыты ли 80 и 443; в панели Timeweb нет ли отдельного файрвола, закрывающего порты |
| Страница входа открылась, но вход не проходит | Логин и пароль — ровно как в `.env` (`ADMIN_LOGIN`, `ADMIN_PASSWORD`). После 5 неверных попыток вход блокируется на 15 минут |
| Поменяли `ADMIN_PASSWORD` в `.env`, а старый пароль всё ещё действует | Так и задумано: администратор создаётся только при первом запуске. Смена пароля в интерфейсе появится на этапе 3 |
| С доменом нет замка / ошибка сертификата | `getent hosts <домен>` должен вернуть IP сервера; порт 80 открыт. Журнал: `docker compose logs --tail 50 caddy` |
| `git pull` спрашивает пароль | Вставьте токен из шага 8.1. Если токен истёк — создайте новый |

**Если не помогло** — пришлите мне вывод этих двух команд (из `~/labscaner/deploy`):


## Приложение. Вход по SSH-ключу вместо пароля (по желанию)

Ключ надёжнее пароля и избавляет от ввода пароля при каждом подключении.

1. На **своём компьютере** в Терминале:
   ```
   ssh-keygen -t ed25519
   ```
   На все вопросы — Enter (можно задать фразу-пароль для ключа).
2. Покажите открытую часть ключа и скопируйте всю строку (начинается с `ssh-ed25519`):
   ```
   type $env:USERPROFILE\.ssh\id_ed25519.pub
   ```
3. На **сервере** под `deploy`:
   ```
   mkdir -p ~/.ssh && chmod 700 ~/.ssh && nano ~/.ssh/authorized_keys
   ```
   Вставьте строку (правая кнопка мыши), Ctrl+O, Enter, Ctrl+X. Затем:
   ```
   chmod 600 ~/.ssh/authorized_keys
   ```
4. Отключитесь и подключитесь снова (`ssh deploy@<IP>`) — пароль спрашивать не должны.
