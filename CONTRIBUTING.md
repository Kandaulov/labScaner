# Как ведём работу

## Ветки
- `main` — всегда рабочее состояние, прямые коммиты запрещены (кроме документации на этапе 0–1).
- `feature/<кратко>` — новая функциональность, одна задача из ROADMAP = одна ветка.
- `fix/<кратко>` — исправление дефекта.
- `docs/<кратко>` — только документация.

## Коммиты
На русском, в повелительном наклонении, первая строка до 72 символов:
```
Добавить разбор темы письма

Поддержаны тире –, — и - с пробелами, префиксы Re:/Fwd:.
Refs #12
```

## Pull Request
- Описание по шаблону: что сделано, ссылка на задачу/ADR, как проверить.
- CI зелёный: `dotnet build` без предупреждений, `dotnet test`, `dotnet format --verify-no-changes`.
- Новое архитектурное решение → сначала ADR в `docs/DECISIONS.md` в том же PR.
- Отметить выполненный пункт в `docs/ROADMAP.md`.

## Роли
Работа с ИИ-ассистентом идёт через роли из `.claude/agents/`:
- **architect** — решения и ADR, код не пишет;
- **developer** — реализация задачи с тестами;
- **tester** — тест-план, тестовые данные, автотесты, дефекты.

## Секреты
Никаких паролей, токенов и ключей в репозитории. Локально — `dotnet user-secrets` или `.env`
(в `.gitignore`); пример — `deploy/.env.example`.

## Тестовые данные
Реальные письма и работы студентов в репозиторий не кладём. В `tests/fixtures/` — только
синтетические данные с вымышленными ФИО.
